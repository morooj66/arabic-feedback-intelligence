# Runtime dependencies for the deployed Reviewer API server only
# (scripts/serve_reviewer_api.py's import chain: http_api.py,
# excel_review_flow.py, frozen_inference.py, auth.py, etc.).
#
# This is a trimmed copy of requirements.txt for the Docker image only —
# requirements.txt (the full dev/test set) is unchanged and still what
# local development, the test suite, and the training/calibration wizard
# scripts use. Nothing here changes any application code or behavior;
# it only controls what gets installed in the container.
#
# Excluded, and why (confirmed unused by the server's own import chain —
# grep across src/rcs/review/, src/rcs/classification/,
# src/rcs/training/hf_loading.py, src/rcs/training/sentiment_pretrained.py,
# config/settings.py, and scripts/serve_reviewer_api.py):
#   - gradio: only used by scripts/run_calibration_wizard.py and
#     scripts/run_b3_wizard.py (offline labeling tools, not the server).
#     Its huge, fast-moving transitive dependency tree also made pip's
#     resolver backtrack across dozens of gradio versions during a real
#     build attempt (50+ minutes, still unresolved) — removing it is both
#     correct (unused) and materially faster to build.
#   - pytest: test runner, never imported by any src/rcs/review/*.py
#     module at runtime.
#   - datasets, accelerate: training/model-selection tooling
#     (scripts/run_model_selection.py, Colab notebooks). Frozen inference
#     only ever calls transformers' AutoModel/AutoTokenizer.from_pretrained()
#     directly for a plain CPU forward pass — neither package is touched.
#     datasets' transitive pyarrow dependency (47MB) was also the single
#     slowest, least reliable download in a real build attempt.
